# Set Meeting Tracks Item (Document) Homepage

## Overview

On the Meeting Tracks **group homepage** (see
`Set-Meeting-Tracks-Groups-Homepage`), expanding a meeting lists its documents.
Clicking a document opens its **item homepage** in the content window — the
detail view for a single meeting document. For Meeting Tracks, the "item" is a
**document** (the analog of a Paper Trails issue's detail view).

The item homepage is the Meeting Tracks counterpart of the Paper Trails
document summary view, and shows, in this order:
- A **back link** ("← `<group>` meetings") returning to the group homepage.
- An eyebrow `<COMMITTEE> · <date>`.
- **(1) The document title** — the readable title from the per-document report,
  not the raw filename (the filename is shown small under the download button,
  and is the tooltip in the group list).
- Tag chips: document type, agenda item, file format.
- **(2) Executive Summary** — 2–4 sentences read out of the document itself,
  with a graceful note when it has not been generated yet.
- **(3) Full Document** — a **Download full document** button carrying the
  `download` attribute, so the original is saved to the viewer's download
  folder rather than opened in the browser's PDF viewer:
  `/Power.Talks/Documents%20Database/ERCOT.STKHDR.MEETS/<COMMITTEE>/<date>/<file>`
- Then the metadata: **Committee**, **Meeting date**, **Document type**, and
  **Presented by** when the report names a sponsor.

Right panel ("Quick runs"):
- **(4) For the talk** → `MeetingDocProfileCard`: the document's title and type
  badge over **Sponsor**, **Company**, **Stakeholder Meeting**, **Meeting
  Time**. This replaced `MeetingProfileCard` on the item page — the *group*
  homepage still shows the meeting/group profile, but once a document is open
  the card is about that document and who presented it.
- **Artifacts** → the full `ARTIFACTS` list (the Market Rules right-panel
  setting).

Title, executive summary, sponsor and company all come from the meeting
`Profile.json`'s `document_reports` array, matched on the filename — see
`Set-Meeting-Tracks-Document-Summary`, which generates them. The download link
never waits on that fetch: a document with no report yet still opens.

## File Map

| File | Role |
|---|---|
| `html/src/meetingtracks.jsx` | `MeetingTracksItemHome` (`window.MeetingTracksItemHome`): props `{ committee, date, file, groupName, onBack }`; fetches the meeting `Profile.json`, finds its `document_reports` entry by `file`, renders title → executive summary → download button → metadata; `docExt`/type map. |
| `html/src/app.jsx` | `activeMeetingDoc = { committee, date, file }` set by `onMeetingDocClick`; the render branch shows `MeetingTracksItemHome` when `activeMeetingDoc` is set, `onBack` clears it back to the group homepage. `activeMeetingDate` is set to the document's date (drives the profile). |
| `html/src/rightpanel.jsx` | `ctx.meetingDoc` makes `isMeetingGroup` true (→ full Artifacts) **and** routes "For the talk" to `MeetingDocProfileCard` ahead of `MeetingProfileCard`; the group homepage (`ctx.meetingGroup`, no `meetingDoc`) still gets `MeetingProfileCard`. |

## Navigation model

```
Meeting Tracks tree  ──click group name──▶  Group homepage (meeting list)
                                              │
                                  ──click a document──▶  Item homepage (this skill)
                                              ◀── back link ──
```

State lives in `app.jsx`: `activeMeetingGroup` (committee) → `activeMeetingDoc`
({committee, date, file}). The content branch renders item ▸ group ▸ tree in
that precedence. Leaving the Meeting Tracks section resets all three.

## The document link

`MeetingTracksItemHome` builds the open URL from the committee folder, the ISO
date folder, and the filename, each `encodeURIComponent`-escaped:

```
/Power.Talks/Documents%20Database/ERCOT.STKHDR.MEETS/<committee>/<date>/<file>
```

This is the real downloaded file under `Documents Database/` served by WAMP — so
it only works over `http://localhost`, not `file://`. ZIP bundles download;
PDFs/Office files open or download per the browser.

## The document report

The per-document content (title, executive summary, sponsor, company) is
generated by
`Database Codes/download_STKHDR_Meets/gen_stkhdr_doc_summaries.py` into
`document_reports` on the meeting `Profile.json`. See
`Set-Meeting-Tracks-Document-Summary` for the schema, the reading strategy and
the measured backfill cost.

To add further content here (an extracted agenda section, ballot detail), add a
field to that generator rather than introducing a second fetch — the item page
and the right-panel card already read this one file, and both keep a graceful
"not yet generated" fallback. Never block the download link on the fetch.

## Rebuild & Verify

1. `python "html/rebuild_standalone.py"`.
2. Hard-refresh, open Meeting Tracks → a group → expand a meeting → click a
   document.
3. Confirm: the title is the readable document title, the Executive Summary
   renders (or shows its "not summarized yet" note), **Download full document**
   saves the original to the download folder, the back link returns to the
   group, and the right panel shows Sponsor / Company / Stakeholder Meeting /
   Meeting Time plus full Artifacts.

## Common Mistakes

| Mistake | Fix |
|---|---|
| Download link 404s | Path must be `/Power.Talks/Documents%20Database/ERCOT.STKHDR.MEETS/<committee>/<date>/<file>`, %-encoded; WAMP must be running |
| Clicking the link opens the PDF viewer instead of saving | The anchor needs the `download` attribute, not just an href |
| Title shows the raw filename | No `document_reports` entry for that file yet — run `gen_stkhdr_doc_summaries.py <CMTE> <date>` (filename-only is free) |
| Right panel shows the meeting profile, not the document | `ctx.meetingDoc` must be checked **before** `isMeetingGroup` in the "For the talk" chain |
| Editing `src/*.jsx` and expecting the page to change | Run `html/rebuild_standalone.py` |
| Item view shows the trimmed 3 artifacts | `ctx.meetingDoc` must be in context so `isMeetingGroup` is true → full list |
| Back link lands on the tree | `onBack` should clear only `activeMeetingDoc` (back to the group), not the group too |
| Sponsor/Company both "—" | They are read out of the document by `--ai`; the document may name neither, or has not been read yet |
| Profile card empty | `activeMeetingDate` must be set to the document's date when the item opens |
